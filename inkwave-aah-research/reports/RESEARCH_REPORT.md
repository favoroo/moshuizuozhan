## 1. 项目概况与架构定位

INKWAVE 是一款纯前端实现的 4v4 涂地对战 Web 游戏（技术栈为 **Three.js + 原生 ES6 模块 + Web Audio + Canvas**），支持离线单机（带 7 名 Bot）与基于 WebRTC/WebSocket 的轻量级多人联机。

- **代码结构**：未采用任何混淆打包，直接以标准 ES6 模块组织，共 74 个源码文件，架构层次极度清晰：
  - `core/`：主渲染、多输入设备抽象（鼠标键盘/手柄）、事件总线；
  - `world/`：关卡几何体、Paint 贴图装箱与着色器注入、环境渲染；
  - `game/`：运动控制器（Actor）、武器射击与弹丸池（Weapons/Projectiles）、小地图（Minimap）、导航图与 AI（Nav/Bots）；
  - `ui/`：DOM + SVG 驱动的像素级高完成度 HUD、小地图、设置与菜单；
  - `audio/`：基于 Web Audio 的**零外部文件纯程序化音效与音乐合成引擎**。
- **体量与轻量化**：游戏加载速度在 1 秒以内，因为**所有角色模型、道具网格、贴图甚至音效全部由代码程序化生成**，无庞大 glTF 或音频包加载开销。

## 2. 涂地与墨水系统底层解构（核心重点）

INKWAVE 能够呈现媲美原版《Splatoon》的液体果冻质感、动态水花边缘和完全精确的占地判定，其底层是一套**GPU 渲染与 CPU 玩法逻辑严格同步的双层架构**（见 `src/world/paint.js` 与 `src/world/inkShading.js`）。

### 2.1 GPU Atlas 装箱（Shelf Packing）
- 场景中所有允许涂色的表面（Face，包括地面、斜坡、箱体、垂直墙壁）按面积大小展开在单一巨大的纹理图集（Render Target Atlas，低画质 2048×2048，高画质 4096×4096）中。
- 采用**货架装箱算法（Shelf Packing）**：每个 Face 四周保留 8 像素安全边距（Padding）以防 Mipmap 采样渗色；根据 Atlas 尺寸自动二分尝试计算最佳像素/米密度（`ppm`），确保全部面紧凑排列。

### 2.2 Atlas 颜色编码与混合（RGBA8）
每个像素经过预乘 Alpha 处理，各个通道承载极其精妙的信息：
- **R 通道（队伍占领 Team Share）**：`0.0` 代表队伍 0（Alpha），`1.0` 代表队伍 1（Bravo）。采用 `Over` 混合模式：新涂抹的墨水直接覆盖旧墨水。
- **G 通道（湿润度 Wetness）**：新落地的墨水为 `1.0`，着色器每帧执行干燥 Pass，经过约 6 秒指数级衰减到 `0.0`。湿润状态下的墨水具有更高的镜面高光、更饱满的凸起感和更强烈的表面反射。
- **B 通道（色调抖动 Tone）**：单次落墨的微小颜色明暗扰动，使大面积墨水不会出现纯色单调感。
- **A 通道（覆盖率 Coverage）**：保持约 3 个纹理像素宽度的连续平滑渐变，混合模式为 `MAX`。多次重复涂同一位置具有幂等性，保证扩散动画重绘时边缘稳定。

### 2.3 CPU / GPU 一致性函数 `blobWobble`
为了让 CPU 端的判定（“我脚下踩的是谁的墨水？”、“队伍占领百分比是多少？”）与 GPU 着色器上渲染出的多边形飞溅形状 100% 契合，作者设计了数学函数：
```javascript
export function blobWobble(ang, seed) {
  return 1 + 0.12 * Math.sin(3 * ang + seed * 6.2831) 
           + 0.08 * Math.sin(5 * ang + seed * 17.0) 
           + 0.05 * Math.sin(7 * ang + seed * 41.0) 
           + 0.03 * Math.sin(11 * ang + seed * 73.0) 
           + 0.018 * Math.sin(17 * ang + seed * 29.0) 
           + 0.17 * Math.pow(Math.max(Math.cos(ang - seed * 37.7), 0), 28) 
           + 0.12 * Math.pow(Math.max(Math.cos(ang - seed * 53.3 - 2.1), 0), 36);
}
```
- **CPU 端**：在每个 Face 维护 0.25 米分辨率的粗糙网格，用该函数计算墨滴多边形范围，实时增减占地计数 `counts[team]`，并用于物理接地采样。
- **GPU 端**：顶点着色器和片元着色器执行完全相同的数学振幅公式。只有细微的外部溅射卫星水珠（Satellites）和垂直墙壁下垂流挂（Wall Drips）作为纯 GPU 装饰，不占领实际地块，兼顾了判定绝对公正与视觉丰富度。

### 2.4 着色器渲染（Ink Shading）的视觉高级感
1. **三次 B 样条近景重建（Cubic B-Spline）**：着色器通过 12 次双线性采样计算三次 B 样条，在近距离观察时完全消除像素马赛克，输出平滑无棱角的圆形曲面高程场。
2. **分析法线与边缘弯液面（Meniscus Lip）**：通过样条一阶导数计算解析法线，在墨水边缘形成自然鼓起的果冻微凸边缘。
3. **两队交界重叠缝（Overlap Lip & Crease）**：新墨水骑在旧墨水上方；当两滩墨水都干燥时，交界处呈现自然的微小凹缝。
4. **接触阴影（Contact Shadow）**：着色器根据太阳入射角计算墨水表面向地面的微弱投影，使墨水有明显的“厚度立体感”。
5. **动态涟漪（Dynamic Ripples）**：系统支持最多 24 个动态涟漪通道（记录世界坐标、出生时间、波长、振幅、波速），角色落水、走动、炸弹爆炸会向四周扩散波纹，扰动着色器法线。

1. **弹道仰角反向修正（Ballistic Launch-Pitch Correction）**：

2. **GPU Instancing 零 GC 弹丸管理**：
   全场最多 512 颗墨水弹丸，仅用一个 `THREE.InstancedMesh` 合并绘制，拉伸比例（aShape）动态反映弹头圆弧与细长水流尾巴。

## 4. 副武器与终极大招设计

### 4.1 副武器：Splat Bomb（吸盘/定点炸弹）
- **数值**：耗墨 70 点（满墨 100 点，投掷后墨水仅剩 30%）；投掷速度 13.5 m/s；引信延迟 0.95s。
- **杀伤与涂地**：中心最大伤害 180（秒杀），外圈保底伤害 35，杀伤半径 3.1m，涂地半径 2.7m。
- **交互细节**：按住副武器键时，HUD 会以 64 点虚线投射抛物线轨迹，并在地面投射落点圆环。

### 4.2 终极大招（Specials）
通过涂地增加面积累加能量槽（170~195 点）：
1. **Tidal Slam（超级降落 / 砸地）**：
   - 蓄力升空 0.55s，滞空 0.25s，随后以巨大威能猛烈砸向地面。
   - 击杀半径 3.2m（伤害 180 秒杀），冲击波扩散半径 5.2m（伤害 55），在地面炸出巨大圆形墨水滩。
2. **Ink Tempest（墨水暴风雨）**：
   - 投掷发生器，在空中生成一团盘旋移动的墨云（持续 6.5s，半径 3.4m，漂移速度 1.1m/s）。
   - 墨云下方持续下墨雨，对范围内敌方造成每秒 34 点持续伤害，并迅速将下方地面涂满本方墨水。

## 5. 角色机动、潜墨与物理控制

角色控制器位于 `src/game/actor.js`，采用基于运动学（Kinematic）的角色控制器，其手感极其丝滑（见 `PLAYER` 配置）：

### 5.1 人形态（Kid） vs 鱿鱼潜墨形态（Squid）
- **形态速度**：人形态走动移速 6.0 m/s；干地/未涂墨地面的鱿鱼跳跃移速 2.9 m/s；**己方墨水中潜水移速高达 11.8 m/s（接近人形态 2 倍速度）**；踩敌方墨水移速剧降至 1.9 m/s。
- **形态切换竞态裁决**：
  - 射击键与潜水键同时按下时，以**最新按下（Timestamp）的为准**。
  - 从墨水潜行中钻出（Pop-out）开火时，存在 `emergeDelay (0.07s)` 延迟，开火输入自动进入缓冲队列（`fireBuffer 0.16s`），绝不会吞键。
- **回墨与回血速率**：
  - 潜入己方墨水：回墨速度高达 **42 点/秒**（满墨仅需 2.38 秒！），回血速度 **60 点/秒**（满血 100 仅需 1.66 秒）。
  - 人形态：停火延迟 0.9 秒后，回墨速度仅 9 点/秒（满墨需 11 秒）；脱战 1.3 秒后，回血速度 22 点/秒。

### 5.2 踩敌方墨水的惩罚与保护机制
- **DOT 掉血**：踩在敌方墨水上每秒扣 20 点血。
- **斩杀保护（Damage Cap）**：**单靠踩敌方墨水扣血有上限，最多扣 40 点（即生命值绝不会低于 60 HP）**！踩墨绝不会直接致死，必须有敌人武器伤害配合才能击杀。离开敌方墨水后，踩墨受击槽以 30 点/秒恢复。
- **机动惩罚**：移速降至 1.9 m/s，跳跃速度削减至原本的 72%。

### 5.3 垂直爬墙与台阶翻越（Wall Climb & Ledge Pop）
- **爬墙吸附**：面对垂直墙壁（法线倾角 `< 0.5`）按住潜水键并向前推摇杆，若墙面涂有己方墨水，角色立即吸附并以 7.5 m/s 向上爬升，且能左右横移。
- **翻越台阶（Ledge Pop）**：向上爬行时上方射线探测到墙壁结束，自动触发翻越动作，以垂直初速度和水平推力跃上平台（Pop-up）。
- **蹬墙跳脱离**：在墙上向后拉摇杆，以 3.2 m/s 反向弹开墙壁。

### 5.4 超级跳（Super Jump）
- 死亡复活或在场内任意时刻，可呼出小地图选择队友或出生点，蓄力后化作乌贼划过全场高空弧线降落，降落点提前在地面向全场显示预警光圈。

## 7. Bot AI 与导航寻路系统

针对单机 + Bot 对战，INKWAVE 编写了一套非常逼真、拟人度极高的 AI（`src/game/bots.js` 与 `src/game/nav.js`）：

### 7.1 人性化物理瞄准（Humanized Aim Spring）
- 杜绝瞬移锁头。Bot 瞄准采用**二阶临界阻尼弹簧（Critically-damped spring）**平滑转向，并限制最大角速度（Easy: 7 rad/s, Normal: 10 rad/s, Hard: 14 rad/s）。
- 叠加上一层缓慢随机游走的瞄准误差（Perlin 噪声漂移），以及初次发现目标时的**瞄准过冲与修正（Overshoot & Correction）**，模拟人类玩家的拉枪手感。

### 7.2 决策状态机（Decision Tree）
- **边走边涂（Paint on the Move）**：Bot 前往交火点过程中，会左右扫射将未涂地块和敌方墨水铺上己方颜色。
- **墨水管理与回潜**：当墨水低于 20% 时，主动潜入己方墨水 1~2 秒恢复弹药。
- **劣势撤退（Tactical Retreat）**：对枪中自身血量低于 40 且处于劣势时，Bot 会立刻掉头向后方己方墨水潜行逃离回血。
- **超级跳支援（Super Jump Reinforce）**：Bot 在出生点复活后，有 50% 概率评估前线队友位置，若队友周围安全且离前线较近，直接发起超级跳降落支援！

### 7.3 3D 导航图（NavGraph）
- 地图按 1 米间隔自动采样可行走平面与高度差。
- 节点之间建立 3 类连边：`Walk`（水平通行）、`Jump-up`（跳上台阶）、`Drop-down`（下落单向边）。
- 采用二叉堆加速的 A* 算法，在己方墨水里寻路代价更低，促使 Bot 沿本方墨水路线高速突进。

## 8. 音效与音乐系统（全程序化合成）

INKWAVE 最不可思议的技术点之一，是其**完全不需要下载任何 `.mp3`、`.wav` 或 `.ogg` 音频文件**，所有 94 个音效和整套 BGM 全部用 Web Audio API 动态合成（见 `src/audio/audio.js` 与 `src/audio/music.js`）：
- **气泡与水感质感（Wet Layers）**：使用 FM 频率调制、粉红噪声（Pink Noise）、带通滤波器扫描模拟墨水击中、下潜水花、咕嘟冒泡声。
- **空间 HRTF 3D 声相**：配合每帧摄像机位置和朝向，计算距离低通衰减（Low-pass cut）和广场混响卷积（Convolver Reverb）。
- **动态混音闪避（Ducking）**：玩家被击杀、终局哨声或重要事件触发时，BGM 自动下压闪避。

> **对应价值**：这与我们 P1 项目现有的 `tools/bake_sfx.py`（纯标准库离线音效烘焙工具）理念完全一致！我们已将所有 94 个音效配方提炼至 `inkwave-aah-research/assets/audio/sfx-catalog.json`，可直接转换为我们 Python 烘焙脚本的参数！

## 9. 对我们 P1（Unity 6 URP 俯视角涂地对战）的系统性参考与落地改造建议

由于我们的 P1 是 **俯视角（Top-Down / Isometric）**，而 INKWAVE 是 **第三人称越肩视角（Over-the-shoulder TPS）**，二者核心玩法虽然都是“涂地对战”，但在视角、操作逻辑和视觉呈现上有本质差异。以下是具体改造与借鉴建议：

### 9.1 视角差异带来的玩法重构与设计调整

| 玩法维度 | INKWAVE (越肩 TPS) | P1 (俯视角 Top-Down) 改造方向 |
|---|---|---|
| **视野与信息感知** | 背后盲区大，需要频繁转动视角观察背后墨水与敌人 | **全图一览无余**：俯视角天然具备小地图级别的全局信息。因此**潜墨隐匿（Stealth）**变得更为关键：在敌方视野内，只要潜入己方墨水静止或慢速移动，应完全隐形，只在高速潜游时产生微弱涟漪 |
| **瞄准与射击操作** | 准星位于屏幕中央，依靠鼠标/右摇杆瞄准空间准点 | **双摇杆射击（Twin-stick Shooter）**：左摇杆移动，右摇杆朝任意 360 度方向指向射击，地面实时投射射击方向与落点范围指示扇面/光带 |
| **高低差与掩体** | 依靠抬头/低头瞄准高台，高低差显著 | 俯视角下高台容易遮挡下方角色，建议：<br>1. 场景以平原和矮台阶为主（高度 ≤ 1.5m）；<br>2. 建筑物和掩体使用半透明遮挡剔除（X-Ray / Dither Fade）；<br>3. 抛物线武器（如泼桶、炸弹）提供明显的地面落点阴影光圈 |
| **爬墙机制适配** | 视角跟随爬上垂直墙壁 | 俯视角爬墙会导致相机遮挡。建议**简化为“墨水梯/单向墨水滑索”**，或仅允许在特定矮墙快速翻越，避免垂直空间视角错乱 |

---

### 9.2 涂地系统在 Unity 6 URP 中的落地建议

当前 P1 的第一阶段已有基于网格的简易原型。结合 INKWAVE 的工业级方案，建议进阶方案如下：

1. **GPU 绘制层（URP Custom Render Pass / Compute Shader）**：
   - 使用一张全场正交投影的 `RenderTexture`（例如 2048×2048，格式 `R8G8B8A8_UNORM`）。
   - 弹丸落地时，在 Compute Shader 或通过 `Graphics.DrawMeshInstanced` 绘制墨滴 Quad 到 RT 上。
   - 沿用 INKWAVE 的通道设计：**R 队伍归属、G 湿润度、A 覆盖率**。
2. **URP 墨水 Shader 特效**：
   - 地面材质在 Shader Graph / Custom URP Shader 中采样该 RT。
   - 利用 INKWAVE 的**样条导数梯度法**计算表面法线微凸（Meniscus Lip），叠加环境反射（Smoothness 在湿润区提高至 0.95），瞬间大幅提升水感表现。
3. **CPU 逻辑层（同步判定）**：
   - 采用类似 INKWAVE 的 0.25 米网格（`InkGrid.cs`），或直接通过 `AsyncGPUReadback` 按 5~10Hz 低频抓回覆盖率用于计分，保证无 GC 与主线程零卡顿。

### 9.5 Bot AI 的四步落地路线

利用 INKWAVE 的经验升级 P1 的 Bot FSM：
1. **二阶阻尼瞄准（Aim Spring）**：右摇杆指向不要直接瞬移设置 `transform.rotation`，使用阻尼插值，模拟手柄摇杆的自然平滑拉枪。

3. **残血战术回潜**：HP < 40 时脱离攻击状态，进入逃跑状态，钻入己方墨水静止回血。
4. **出生点超级跳**：复活时评估前线队友，若距离 > 18 米且队友处于安全区域，触发抛物线大跳降落。
