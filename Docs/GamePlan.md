## 1. 一句话定位

第三人称 3D、短局制（3 分钟）团队涂地对战。玩家在己方墨水中潜行加速、补给，
用武器涂满地面，结算时覆盖率高的队伍获胜。

**先做「一个人 + 一堆 Bot」的可玩垂直切片，不做联网；桌面为主，Android 同步验证。**

## 2. 核心循环

```
出生 → 移动/涂地 → 墨水耗尽 → 潜入己方墨水回复
     ↘ 遭遇敌人 → 交火 → 击杀 / 被击杀 → 复活
              ↘ 比赛结束 → 覆盖率结算 → 重开
```

三个必须做对的体验点：

1. **涂地要爽**：命中地面的即时反馈（音效、溅射、颜色扩散动画）。
2. **墨水是资源也是地形**：己方墨 = 高速 + 补给；敌方墨 = 减速 + 伤害。
3. **地图控制感**：随时能看到双方覆盖率，落后时知道该往哪涂。

## 3. v1 范围

**做：** 单张 40×40m 对称高低台+斜坡+出生安全区地图、1 套完整武器组合（连发喷射枪 + 抛物线延时手雷 + 超级墨水砸地大招）、1 个玩家 + 3 个友方 Bot vs 4 个敌方 Bot、沿途滴落+终点爆斑涂地、按键切换潜行形态、击杀爆墨/安全区复活、2 分钟快节奏比赛、右上角实时涂地小地图、开始叠层 → 3-2-1 GO → FINISH 定格与覆盖率滚动结算 → 一键重开、23 个烘焙音效与溅射粒子；桌面可玩 + Android 可出包运行。

**不做（v2 以后）：** 真人联网、多主武器切换、复活超级跳（Super Jump）、角色自定义、氪金/账号、关卡编辑器、iOS、美术资源精修。

## 4. 关键技术决策

### 4.1 3D + 第三人称轨道相机（Inkwave 同款，而不是纯 2D 或固定俯视）

| 需求 | 3D 第三人称轨道相机 | 纯 2D / 固定俯视 |
|---|---|---|
| 寻路 | 自定义 NavGrid (80x80) A* | 要切片写 2D 寻路 |
| 涂地渲染 | 世界坐标映射贴图，天然支持斜坡与高台 | 需要切分精灵 |
| 高低差/掩体 | 越肩视角直接看到高台立面、斜坡与掩体后的空间关系 | 俯视易压扁为 2D 贴纸，分不清高度 |
| 射击手感 | 屏幕中心准星 + 相机中心射线，远近目标都能瞄 | 鼠标地面求交只适合平地，打不到空中/墙面 |

结论：**用 3D，相机采用 Inkwave 式第三人称轨道相机**：枢轴 1.85m（潜墨 1.30m）、
吊臂 4.5m（潜墨 4.1m）、FOV 52°、俯仰 -60°~+66°、球探针防穿墙、贴墙右肩偏移。
WASD 相对镜头移动，屏幕中心准星即相机中心射线；鼠标 / 右摇杆 / 触屏滑屏转视角。
类名 `TopDownCameraFollow` 保留以兼容旧调用方，内部实现已切换为第三人称。

### 4.2 涂地系统：CPU 网格 + Texture2D（v1 首选）

不用 RenderTexture/Decal，因为涂地状态必须能被**玩法查询**（脚下是什么墨、能不能潜、
敌方墨减速），CPU 网格天然满足，也容易写 EditMode 测试和以后做同步。

**规格：**

- 地图 40m × 40m：桌面 0.2m/格 → 200 × 200 = 40,000 格；移动端 0.3m/格 → 133 × 133 ≈ 17,700 格
- `byte[] owner`：0 = 空地，1 = A 队，2 = B 队
- `bool[] blocked`：墙/不可涂区域（初始化时用 Physics 检测生成）
- `Texture2D` 与网格同分辨率（桌面 200×200，移动端 133×133），RGBA32，格子与像素一一对应
- 涂色 API：`Paint(Vector3 worldPos, float radius, byte team)`
  - 取 AABB 内格子，距离判断，写 owner + 颜色 + 计数
  - 标记 dirty，**每帧最多上传一次贴图**
- 查询 API：`InkAt(Vector3 worldPos) → byte`，供移速、潜能、回复、Bot 决策使用
- 覆盖率：增量维护 `int[] paintedCount`，`覆盖率 = count[team] / 可涂格总数`
- 地面 Shader：世界坐标 XZ → UV 采样墨水贴图，与底色混合；采样用双线性让边缘平滑
- 比赛开始/重开：清空网格与贴图

**立面墙涂地与潜行上爬（2026-10-28 追加）：**

- 每张竖直立面各一套独立 2D 墨格：用「平面原点 + U/V 轴 + 法线」把世界坐标投影成米制面坐标
  （`InkWallFace`，纯 C#，可 EditMode 单测），默认 `0.1m/格`
- 渲染不改造墙体 Shader：按 BoxCollider 包围盒生成 4 张外扩 1cm 的透明 Quad，
  每面一张运行时贴图经 `MaterialPropertyBlock` 绑定；未涂区域 alpha=0，原水泥墙外观完全不变
- 涂色来源：主武器弹丸命中立面直接涂该面；手雷 / 大招 / 击杀爆墨按「球与面的相交圆」涂附近墙面
- 潜行上爬：贴着己方墨墙按住潜行键并向墙内推 → 沿墙面上爬，横向输入可沿墙面平移，
  松开潜行、脱离墙面或墙面变敌方墨即脱落；爬到距墙顶 0.4m 内自动翻上墙顶。
  墙面墨**不计入覆盖率**，攀爬期间不回墨 / 不回血（避免挂墙无限补给）
- 只有玩家可攀爬：Bot 通过 `AllowWallClimb=false` 关闭，寻路仍只走 NavGrid 地面

**为什么不用 GPU：** RenderTexture 方案边缘更好看，但玩法侧读回数据要靠
`AsyncGPUReadback`（延迟 1~2 帧、难测试、不同平台行为不一致）。等原型验证
性能不够（>2048² 或大量涂色单位）再升级为 Compute Shader，接口保持不变。

**性能预算：** 单次 Paint 半径 1.5m ≈ 半径 7.5 格 ≈ 180 格；每帧几十次 Paint
完全无压力。桌面贴图 200×200 约 160KB，即使每帧全量上传也只有约 10MB/s。

### 4.4 主武器、副武器（延时手雷）与大招（砸地冲击波）

- **主武器（连发喷射枪）配置 SO**：`fireInterval 0.12s / damage 34 / projectileSpeed 25 m/s / maxRange 12m / spread 4° / inkCost 1.2 / trailDropInterval 0.085s / trailSplatRadius 0.45m / endSplatRadius 0.95m`
  - 弹丸使用**对象池**，每帧做 SphereCast 防穿透
  - 飞行途中每隔约 2.2m 在下方地面滴落小墨斑（0.45m），命中地面/墙体或到达最大射程爆开大墨斑（0.95m），边走边射自动铺出连贯墨水路
  - 命中敌人扣血并在敌人脚下爆小墨斑；击杀敌人时在敌人位置爆出击败方大墨斑（半径 1.8m）
- **副武器（抛物线延时墨水手雷）**：
  - 消耗 `55` 墨水，向准星位置（最远 12m）抛物线投出
  - 触地后停止并显示 `0.8s` 闪烁预警圈，引爆后涂地半径 `3.0m`，内圈 `1.6m` 造成 `120` 伤害（秒杀），外圈 `50` 伤害
- **大招（超级墨水砸地冲击波 Splashdown）**：
  - 每次有效涂地（新增或覆盖敌墨）累积能量，满 `100` 点就绪（播放 `ult_ready_1.wav`）
  - 按 `Q` / 大招键原地跃起蓄力 `0.4s`（期间无敌 + 地面显示 `5.0m` 预警圈 + 播放 `ult_cast_1.wav`），随后猛砸地面瞬间涂满半径 `5.0m` 本队墨水，内圈 `3.2m` 造成 `150` 伤害（秒杀）

### 4.5 Bot AI

NavMesh（烘焙到关卡）+ 简单有限状态机：

```
Patrol/Paint  巡逻并涂地（优先涂未被自己队伍覆盖的区域）
Engage        12m 内发现玩家 → 接近到 8m 开火，保持距离
Refill        墨水 < 15% → 前往最近己方墨水区域
Dead          被击杀 → 5s 后出生点复活
```

Bot 的涂地行为是比赛的核心对手，必须让 Bot **真的去涂地**，而不只是打架。

### 4.6 比赛流程与局势感知

`MatchState` 状态机：`ReadyOverlay → Countdown (3-2-1 GO!) → Playing → FinishFreeze (FINISH!) → ResultScreen → Restart`
- **2 分钟（120 秒）快节奏倒计时**（最后 30 秒倒计时提示，时长由 ScriptableObject 控制）
- **顶部实时覆盖率条**（双方百分比与比色进度条）
- **右上角常驻实时涂地小地图**：直接绑定 `InkGrid` 的 `Texture2D`，叠加不可涂掩体轮廓与玩家/友方位置圆点，零额外渲染开销
- **结算**：`FINISH!` 定格 → 覆盖率百分比从 0 滚动涨到最终值的动画 + 胜负音效
- **重开**：零 GC 清空墨水、重置对象池、归位 8 名角色、重新计时

**开发与验收节奏（已确认）：分两大阶段集中验收**
1. **第一大阶段（Phase A：M0 ~ M3 单人核心手感包）**：一口气交付工程骨架、CPU 涂地网格与世界坐标地面/斜坡着色、移动与潜行形态、沿途滴落+终点爆斑主武器、抛物线延时手雷、跃起砸地大招、第三人称跟随相机、实时小地图、音效粒子与练习木桩靶。完成后供用户集中试玩调优手感。
2. **第二大阶段（Phase B：M4 ~ M6 4v4 完整比赛与双端交付包）**：在第一阶段手感确认后，交付 40×40m 对称高低台+斜坡+安全出生台竞技场、4v4 Bot AI（含 3 友方 Bot + 4 敌方 Bot）、2 分钟完整比赛闭环与结算演出、移动端左摇杆 + 右滑屏视角 + 独立开火键 UI 及双端构建。

### 4.7 平台与输入（桌面 + Android）

**输入方案（新版 Input System 直接轮询 + 触控注入）：**

| 操作 | 桌面 | Android |
|---|---|---|
| 移动 | WASD（相对相机） | 左虚拟摇杆（相对相机） |
| 视角 | 鼠标移动（锁定指针） | 右半屏滑屏；开火/手雷键拖拽也可转视角 |
| 准星 | 屏幕中心固定 | 屏幕中心固定 |
| 跳跃 | 空格键（Space） | 右侧跳跃按钮 |
| 射击 | 鼠标左键 | 右下射击按钮（按住连发、可拖拽压枪） |
| 潜行 | Shift / 鼠标右键（按住） | 左侧潜行按钮（按住） |
| 延时手雷 | E / 鼠标中键 | 副武器手雷按钮（短按秒投 / 长按瞄准） |
| 砸地大招 | Q 键 | 大招大按钮 |

- 形态仲裁采用「最后一次按下的键决定形态」：射击中按潜行会立即停火潜入；潜行中按开火会立即出枪；
  松开开火但仍按住潜行键会自动回到潜行，支持边潜边点射的连打节奏。
- 潜行仍只在己方墨水生效；踩不到己方墨时潜行键不会吞掉开火输入。

- 移动和瞄准都走抽象接口（`IMoveInput` / `IAimInput`），不要让 gameplay 代码直接读键鼠。
- 桌面锁定指针做原生鼠标视角；暂停/选枪/结算自动解锁。
- Android 提供轻量辅助瞄准（中心射线 0.8m 内吸附最近可见敌人），补偿触屏精度。
- 视角灵敏度（鼠标/触控）与反转 Y 在暂停设置中可调，PlayerPrefs 持久化。
- UI 用 Canvas Scaler + Safe Area，按钮最小触控尺寸约 80px（1080p 基准）。

**移动端约束（从第一天就遵守）：**

- 性能目标：桌面稳定 60fps；中端 Android 稳定 30fps 以上。
- 涂地网格分辨率按平台配置：桌面 0.2m/格，移动端 0.3m/格（同一套代码，参数不同）。
- 贴图每帧最多上传一次；移动端降低贴图尺寸（如 200×200）。
- 所有弹丸/特效走对象池；避免每帧 `Instantiate` 与 LINQ。
- 材质用 URP 的移动端友好变体，Android 贴图压缩 ASTC。
- 场景灯光以烘焙为主，实时光只保留必要的一盏。

### 官方方向

Unity 已弃用 `com.unity.ai.assistant` 内置的 MCP server，改为 Unity CLI 的
`unity mcp`（基于 Pipeline）。对能执行 shell 的 Agent，直接用 `unity command`
比走 MCP 更快、更省 token。因此本项目**不额外引入第三方 MCP 服务**。

常用命令（非交互 shell 用绝对路径）：

```bash
U="$HOME/.unity/bin/unity"
"$U" status                            # 编辑器连接状态
"$U" command                           # 列出全部命令
"$U" command script.recompile_status   # 编译状态
"$U" command console.get --tail 50 --level error
"$U" command screenshot --view game --output Logs/shot.png
```
