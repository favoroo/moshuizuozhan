## 0. 结论摘要

| 级别 | 条目 | 一句话 |
|---|---|---|
| **P0-1** | 出生区零保护 | 没有敌方禁入，Bot 会走进你的出生台并把它涂掉（出生台可涂且计分） |
| **P0-2** | 越界软锁 | 出生后靠背 1.2m 可跳上 → 北边界墙 2.4m 再跳一次 → 翻出场地且无法回场 |
| **P0-3** | 掩体顶面计分口径不一致 | 集装箱顶「涂了 0 分」，木箱/花坛顶「涂了算分」，两种一样的箱子行为不同 |
| **P1-1** | 0.2 / 0.3 / 0.65m 死缝 | 看得见、走不进，却计入覆盖率分母（约 8.5 m² 永久涂不到） |
| **P1-2** | 中路两段 8.2m 裸奔 | 出生门到中央高台之间几乎没有掩体，且正对高台射击线 |
| **P1-3** | 侧翼外走廊仅 1.4m | 8 人对抗里两人无法并行（INKWAVE 侧巷是 5~8m） |
| **P1-4** | 南北边界不对称 | 南墙 0.55m + 隐形挡墙，北/东/西 2.4m；旧俯视相机时代的遗留 |
| **P2-1** | 侧翼高台 0.9m 可跳上 | 4 条侧翼坡道（约 63 m²）纯装饰 |
| **P2-2** | `SpawnGate` 与注释不符 | 注释写「两侧挡墙留 7m 出口」，实际每队只有 1 块 3m 挡墙 |
| **P2-3** | 装饰实体道具未注册不可涂 | 与 P0-3 同源：占地约 30~40 m² 仍在分母里，且顶面可刷分 |
| **P2-4** | 死参数 / 移动端精度 | `finalWarningSeconds`、`countWallInCoverage` 无消费者；移动端格子 0.2×0.28m |

**做对了、不要动的部分**（容易被误改）：

- 中央高台 1.1m + 8 段 0.5m 女儿墙，实际边缘高度 **1.6m > 跳跃 1.35m**，只能走 4 个 4.4m 坡道口
  或涂墙攀爬进入 —— 这正是 INKWAVE Kelpline「钢制侧壁只留前后入口」的思路，**不要为了"更好上"把女儿墙拆掉**。
- 全图 **180° 点对称**（旋转对称而非镜像对称），双方完全公平，符合 INKWAVE 的 `single` + `half` 模型。
- 墨水经济与机动数值（潜墨 11.8 / 跑 6.0 / 敌方墨 1.9 m/s、潜墨回墨 42/s、敌墨保底 60 HP、
  跳跃缓冲 0.16s、出水过渡 0.07s）与 INKWAVE `PLAYER` 配置基本 1:1 对齐，属于已经调好的部分。

### 1.3 涂地计分口径

- 计分网格是 **XZ 俯视 2D 网格**：桌面 400×400 覆盖 40×56 → 格子 **0.1 × 0.14m**（非正方）；
  移动端 200×200 → **0.2 × 0.28m**（`InkGridConfigSO.cs:15/19`、`InkGrid.cs:55-56`）。
- 高度不参与计分：高台顶面与它正下方的地面是同一些格子（不会重复计数，但也不可能分别计分）。
- **不可涂格**由障碍 Collider 的 XZ 包围盒烘焙（`InkSurfaceController.cs:228-249` → `InkGrid.cs:111-133`），
  `PaintCircle` 遇到 blocked 格直接跳过（`InkGrid.cs:194-197`）。
- 墙面墨（`InkWallSurface` 的 4 张立面）**完全不计分**，只做视觉与充能（`countWallInCoverage` 是死字段，见 P2-4）。

## 2. 问题清单

### P0-1 出生区零保护（偷家 + 堵门）

**现象**
1. 全项目**没有任何敌方禁入机制**：grep `SpawnBarrier|spawnBarrier|EnemySpawn|禁入|NoEntry|SafeZone` 全空。
2. Bot 的涂地目标评分**主动奖励压向敌方半场**：
   `progress = Clamp01(target.z * enemySideSign / halfDepth)`，`score += progress * 3f`
   （`BotController.cs:937-940`）——越靠近你的出生点越"值得去"。
3. 寻路网格不排除敌方出生区（`NavGrid.Build` 只看碰撞体，`NavGrid.cs:71-124`）。
4. 出生台 **8 × 6.5 = 52 m²/队、共 104 m²（全图 4.6%）可涂且计入覆盖率**
   （`ArenaGeometryBuilder.cs:238-245`；这是 2026-10-30「出生台可喷涂回归」的既定需求，见 OptimizationPlan）。
5. 复活 **4.0s** + 无敌 **3.0s**（`PlayerConfigSO.cs:67/69`），保护只在"阵亡复活"路径授予
   （`CombatantHealth.cs:152-157` 的 `ResetImmediately` 会清零）。

**玩家体感**
复活 → 3 秒无敌 → 敌人的 Bot 就站在出生台上，无敌一结束立刻被围杀；同时你的出生台被刷成敌方颜色，
对方白拿 4.6% 覆盖。这是最容易被玩家判定为"这游戏坏了"的一条。

**建议改法（移植 INKWAVE 的 `spawnPads` + `spawnBarrier: 4.2`）**
- 新增一个 `SpawnZone`（建议放 `Scripts/Environment/`），每队一块，半径建议 **5.5~6m**
  （覆盖 8×6.5 出生台 + 门口，比 INKWAVE 的 4.2m 略大是因为 P1 出生台更大）。
- 物理侧：敌方角色进入半径后被径向推出，实现可挂在 `InkCharacterMotor` 的一个新公共方法上
  （重载 + 默认参数，保持向后兼容）。
- 寻路侧：`BotController.PickPaintTarget` 跳过敌方出生圈内的候选点；撤退 / 补墨目标同样过滤。
  **不要**改 `NavGrid` 的共享可行走掩码（它没有队伍维度，改了对双方都不公平）。
- 注意：Bot 在圈边缘会贴边抖动，建议在目标选择层做"圈外 2m 缓冲区"，物理推出只做兜底。

**成本**：中。触及 `Environment`（新组件）+ `Player/Motor`（推出入口）+ `AI`（目标过滤）三个领域锁，
建议按领域拆成 3 个独立提交，或明确由同一 Agent 一次性交付。

**待实机确认**：Bot 是否真的会走到 `|z| > 21.4` 的出生门之后。几何上没有任何阻挡（已与场景核对），
但 Bot 的路点选择是随机的，实际频率需要用 DebugOverlay 观察 2~3 局。

### P0-2 越界软锁（掉出场地后无法回场）

**现象**
1. 出生后靠背高 **1.2m**（`ArenaGeometryBuilder.cs:208-216`），跳跃 1.35m → **能跳上去**。
2. 北/东/西边界墙高 **2.4m**（`:229-236`），但从 1.2m 的靠背顶再跳一次（1.2m 落差）就能上去。
   靠背 z 范围 25.7~28.3 与北墙 z 范围 28~29 **重叠 0.3m**，等于直接给了台阶。
3. 场地外：`Ground_Main` 只有 40×56，墙外是远景码头基座（顶面 y = −0.15，
   `ArenaDecorationBuilder.cs:189` 建 52 × 1.1 × 68 的基座）。
   **全项目没有 kill plane、没有越界夹紧、没有掉出回收**（grep 为空）。
4. 边界墙的 `InkWallSurface` 全部是 `allowClimb = false`（`ArenaGeometryBuilder.cs:224/230/233/236`），
   从场外 2.4m 高墙爬不回来（跳跃 1.35 也不够）。
5. 南侧是另一种坏法：南墙只有 **0.55m**（`:223-227`），外侧 1m 再放一块 42×3×1 的**隐形**挡墙。
   玩家可以站上 0.55m 矮墙顶（z = −28.5，**已在墨网格之外**）从界外射击，同时脚下永远涂不上墨。

**玩家体感**
"我跳上出生点后面的台子玩，再跳一下，人就在场地外面了，走也走不回来，只能等这局结束。"
这是最容易被录成视频的一条；而且只在**北侧**发生（南侧靠背与矮墙重叠，反而出不去），属于不对称 bug。

**建议改法（三层，任选其二即可闭环）**
- **兜底（必做）**：`MatchManager` 每 0.25s 检查 8 个角色，`|x| > 20.8 || |z| > 28.8 || y < −1`
  → 拉回本队出生锚点（**不判死、不清血量**，避免被当成自杀刷复活）。
- **消除路径**：把出生后靠背从 z = ±27 / 高 1.2 改成与边界墙合并的后靠背（高度 ≥ 2.4 或直接贴到 z = ±28），
  让它不再是一个可站立的台阶。
- **顺手修对称**：南墙 0.55 → 2.4（见 P1-4），删掉 `Boundary_South_Blocker`，南侧就不会再有"隐形墙"。

**成本**：兜底小（1 个文件）；几何部分需要重建场景。

**待实机确认**：从靠背顶跳上北墙的落点是否真的可站（1m 宽的墙顶 + CharacterController 半径 0.45）。
已核对场景：`SpawnTerrace_TeamA` 顶面 y = 1.2、`Boundary_North` 顶面 y = 2.4，两者 z 范围在 28.0~28.3 重叠，
高度差正好 1.2m < 跳跃 1.35m——**几何上成立**，只差落地稳定性。

### P0-3 掩体顶面计分口径不一致（"一样的箱子，一个算分一个不算"）

**现象**
- `CreateCover`（集装箱、掩体墙、挡墙、女儿墙）会把 Collider 注册进 `blockedColliders`
  （`ArenaGeometryBuilder.cs:372-397`）→ 占地烘焙成不可涂。
  于是这些物体的**顶面虽然有墨迹视觉**（材质是 `P1/ObstacleDitherLit`，会采样顶视图集），
  但 `PaintCircle` 会跳过 blocked 格 → **涂了不加分**。
- 装饰实体道具（木箱 / 花坛 / 售卖亭）走的是 `ArenaDecorationBuilder.CreateInkPropProxy`
  （`ArenaDecorationBuilder.cs:550-586`），它只建 `BoxCollider` + `InkWallSurface`，
  **完全没有注册进 `blockedColliders`** → 它们占的地面格仍然可涂，且**涂顶面会直接给分**。
- 而 `PaintCoverageAudit`（`Ink/PaintCoverageAudit.cs:7-20`）只校验"有没有上墨路径"，
  不校验"上了墨算不算分"，所以这条一直没被发现。

**玩家体感**
同一张图里，木箱顶刷一下比分涨，集装箱顶刷一下比分不动。玩家会得出"有的地方刷漆无效"的结论，
然后不再相信覆盖率 HUD。**这一条其实比 P0-1 更容易造成"系统不可信"的感觉。**

**建议改法（二选一，推荐 A）**
- **A（推荐）统一为"实体掩体顶面不计分"**：把装饰实体道具的 Collider 也注册进 `blockedColliders`。
  代价：约 30~40 m² 从可涂面积中扣除（分母变小，双方公平）；收益：全图"箱子顶=装饰"口径一致，
  并且顺带修掉 P2-3。
- **B 统一为"顶面计分"**：把 `CreateCover` 的 Collider 从 `blockedColliders` 里拿掉。
  **不推荐**：那 186 m² 掩体占地会变成"计入分母但只能从顶上涂"的格子，可涂上限反而下降，
  还会让 Bot 的覆盖率评估失真。
- **补充**：给 `PaintCoverageAudit` 增加一条"渲染材质采样顶视图集 且 Collider 在 blocked 名单里"的告警，
  把这类口径不一致变成可自动检出的问题。

**成本**：A 方案小（1 个文件 + 重建场景时生效）。

### P1-1 0.2 / 0.3 / 0.65m 死缝（看得见、走不进，还算分母）

**实测缝隙**（角色直径 0.9m）：

| 位置 | 缝隙宽度 | 重叠长度 | 面积 | 后果 |
|---|---|---|---|---|
| 中央高台 ↔ `CoverWall_00` | **0.20m** | 1.2m | 0.24 m² | 完全封死 |
| `CoverWall_00` ↔ `Container_Mid_SW` | **0.30m** | 1.4m | 0.42 m² | 完全封死 |
| 侧翼高台 ↔ `Container_Flank_West_01` | **0.65m** | 3.6m | 2.34 m² | 完全封死 |
| 侧翼高台 ↔ `Container_Flank_West_02` | **0.65m** | 1.9m | 1.24 m² | 完全封死 |
| `Container_Mid_SW` ↔ 侧翼高台 | 0.95m | 1.1m | — | 仅 0.05m 余量，手感会卡 |

东西两侧镜像 → **合计约 8.5 m²（全图 0.38%）永远涂不到，却始终留在覆盖率分母里。**

**玩家体感**
- 视觉上是一条缝，玩家会反复尝试挤过去，撞墙；
- 覆盖率永远差最后零点几个百分点，"涂满"这个目标不存在；
- Bot 的 0.5m 网格 + 0.386m 采样半径在这些缝隙上会判成不可走（0.65m < 0.772m），
  所以**Bot 和玩家的可行走区域不一致**，容易让人觉得"Bot 会穿墙 / 我不会"。

**建议改法**
- **优先（对齐 INKWAVE 的 `slotSides()` 思路）**：在 `BakeBlockedColliders` 结束后做一次"窄缝封闭"——
  只封闭"两侧都是 blocked、且缝宽 < 0.9m"的格子，从分母里去掉。
  ⚠️ **不要对全图做 0.45m 腐蚀**：那会连"贴墙但可以被炸弹/泼桶/大招溅射涂到"的格子一起删掉，
  可涂面积会掉 5% 以上，而且玩家会因为"墙脚刷不干净"而困惑。
- **次选**：直接改坐标 —— `CoverWall_00/01` 贴死中央台（把 2.6 宽改成 2.0 并内移 0.5m），
  侧翼集装箱内移 0.55m 把 0.65m 缝变成贴死、同时把外走廊从 1.4m 拓到 1.95m（顺带缓解 P1-3）。
  这一步需要重建场景。

### P1-2 中路两段 8.2m 裸奔

**现象**
中路（`|x| < 3.1`）从出生门 z = ±21.4 到中央高台边缘 z = ±5 共 16.4m，全图只有：

- z = ±13.2：`Parapet_TeamA/B_Exit`，**2.6 × 1.0 × 0.8m**（且只有 1.0m 高，只挡得住 80% 身位）
- z = ±11.2：`Barrier_TeamA/B_Left/Right`，各 2.8m 宽，但位于 `|x| = 3.1..5.9`，**不在中路上**

于是中路被切成两段各 **8.2m 完全无掩体**的直道，且正对中央高台（1.1m 台 + 0.5m 女儿墙 = 1.6m 的射击位）。

**玩家体感**
从出生点往前走，8 米内没有任何可以躲的东西，对面站在中央台上就能一路点射到你的出生门。
对照 INKWAVE 的 Kelpline / Tidewater：每条通道（含中路）都有 2~3 层错位掩体，没有一条超过 6m 的纯裸直道。

**建议改法**
- 在 z ≈ ±16.5 与 z ≈ ±9.0 各加一对**错位**低掩体（1.4~1.6m 高，1.6~2.0m 宽）：
  A 半场 z = −16.5 放 `x = −2.4`、z = −9.0 放 `x = +2.4`，B 半场 180° 镜像，形成 S 形推进线。
- 注意别堵住坡道口：`Ramp_South` 的底端在 z = −9.9，x ∈ [−2.2, 2.2]，新掩体要避开这 4.4m 口子。
- 也可以复用现有的 `Planter_Extension`（现在在 `x = ±7, z = ±13.5 / ±19`）：把其中一组挪到 `x = ±2.6`。

### P1-3 侧翼外走廊只有 1.4m

**现象**
`Container_Flank_*` 外沿 `x = ±18.6`，边界墙内表面 `x = ±20.0` → 走廊 **1.4m**。
角色直径 0.9m，两个角色并行需要 ≥1.8m。而这是全图唯一的"贴墙绕后"路线，长度约 40m。

**玩家体感**
- 两人相遇必须有一人贴墙让位，实战里等于"谁先到谁堵住"；
- 4.5m 吊臂的相机在 1.4m 走廊里会被两侧墙夹住，吊臂反复收进 → 视角忽近忽远。

**建议改法**
侧翼集装箱内移 0.55m（`x = ±17.5 → ±16.95`）：0.65m 死缝变成贴死（顺带修 P1-1），
外走廊拓到 **1.95m**。若担心"内侧通道变窄"，可同时把侧翼高台宽度从 4.5 → 4.0。

---

### P1-4 南北边界墙不对称（0.55m vs 2.4m + 隐形挡墙）

**现象**
- 南墙：可见网格 42 × **0.55** × 1（`ArenaGeometryBuilder.cs:223-225`），外侧 1m 处再放
  42 × 3 × 1 的**不可见**挡墙（`:226-227`）。
- 北 / 东 / 西墙：42/58 × **2.4** × 1（`:229-236`）。
- 注释解释了原因：P5-B 时代"南墙网格只有 0.35m，所以碰撞体与墨面都按矮墙建，防越界改由隐形 Blocker 承担"——
  那是**俯视相机**为了不挡屏幕下缘。

**玩家体感**
- 站在南半场回头看是矮护栏 + 港口远景，站在北半场回头是一堵 2.4m 墙 —— **两队观感不同**；
- 朝南墙上方开火会命中一块看不见的东西（墨落在网格外，什么都不发生）= "打空气"；
- 可以跳上 0.55m 墙顶站到墨网格之外（见 P0-2）。

**建议改法**
TPS 相机已经没有"挡屏幕下缘"的顾虑（俯角 +6°、吊臂 4.5m），建议**四面统一 2.4m**，
删掉 `Boundary_South_Blocker`，让"看得见的墙 = 撞得到的墙 = 能涂的墙"三者一致。

**风险**：南侧出生点的相机在玩家背对南墙时会更早触发吊臂收进（北侧现在就是这样的）。
若接受不了，可退而求其次：南墙保持 0.9m（仍可挡子弹、不可站立越界）+ 保留隐形挡墙，但把隐形挡墙的高度降到
可见墙同高，至少让"打空气"消失。

### P2-1 侧翼高台 0.9m 可原地跳上（4 条坡道纯装饰）

**现象**
`HighGround_West/East` 高 0.9m（`ArenaGeometryBuilder.cs:110/127`），跳跃 1.35m → 任何方向都能直接跳上台顶。
配的 4 条坡道（`Ramp_West/East_South/North`，各 3.6 × 4.4m，合计约 63 m²）因此没有玩法意义。

**玩家体感**：不算"难受"，但会让"坡道"这个视觉语言失去可信度 —— 玩家学会"所有台子都能跳"，
之后遇到真正需要坡道的中央台会先尝试跳、失败、再找路。

**建议改法**：二选一
- 把侧翼台抬到 1.5~1.6m（> 跳跃 1.35），坡道变成唯一入口，与中央台形成"两个必须走坡道的高地"；
- 或保持 0.9m，但把 4 条侧翼坡道删掉（省 63 m² 几何与 4 个坡道碰撞体），改成纯粹的"可跳上的矮台阶"。

### P2-2 `SpawnGate` 实现与注释不符

**现象**
注释写「出生网关：z = ±21.4，两侧 1.5m 挡墙，中间留 7m 出口」（`ArenaGeometryBuilder.cs:187-189`），
但实现用的是 `CreateCoverPair`（`:403-417`），它生成的是**原点 180° 镜像件**，
所以每队实际只有 **1 块** 3 × 1.5 × 1.2m 挡墙：B 队在 `x = +5`，A 队在 `x = −5`。

**后果**：出生门没有任何"门"的结构，8m 宽的出生台朝前完全敞开（挡墙在 `|x| = 3.5..6.5`，甚至在台宽之外）。
主场景里也确实只有 `SpawnGate_A`（x=+5, z=+21.4）与 `SpawnGate_B`（x=−5, z=−21.4）两个对象 ——
不是"漏实例化了一个"，而是生成方式本身只产出镜像件。
这与 P1-2（中路裸奔）叠加，构成"出生即暴露"。

**建议改法**：把 `SpawnGate` 改成"每队 2 块"（调用两次 `CreateCoverPair`，或直接 4 次 `CreateCover`），
让注释成真：两块 3m 挡墙 + 中间 7m 出口。这正是 INKWAVE "每个出生区 3 个出口"的最小版本。

### P2-3 装饰实体道具未注册不可涂

见 P0-3 的 B 段。补充数据：`ArenaLayoutV2.Props` 里 `IsSolidProp` 为真的共 **14 件**
（6 个 CrateCluster + 2 个 CrateTall + 4 个 PlanterBox + 2 个 Kiosk，
`ArenaLayoutV2.cs:105-119` 与 `:148-174`），合计占地约 **30~40 m²（1.3%~1.8%）** 未进分母，
且顶面可刷分（旋转后 AABB 会比实际占地略大，这里按"每件 2~3 m²"估算）。
随 P0-3 A 方案一起修。

### P2-4 死参数与移动端精度

- `GameConfigSO.finalWarningSeconds = 30`（`GameConfigSO.cs:18`）**无消费者**：
  UI 用的是 `TopRosterMath.GetTimerPhase` 里硬编码的 60/30（`TopRosterMath.cs:48-52`）。
  改 SO 不会有任何效果，容易误导后续调参。
- `InkGridConfigSO.countWallInCoverage = false`（`InkGridConfigSO.cs:83`）**无消费者**，
  墙面本来就不进地面网格，属于"看起来能配、其实没接线"。
- 移动端 200×200 → 格子 0.2 × 0.28m：半径 < 0.28m 的小墨斑（滴落、擦边溅射）可能整格落空，
  出现"看得见墨、覆盖率不动"的细微不一致。可接受，但值得在移动端出包验收时专门看一眼。

## 6. 复核方法（每条结论怎么自己验）

均为只读操作，不改工程：

1. **几何数值**：直接读 `ArenaLayoutV2.cs` / `ArenaGeometryBuilder.cs` 的常量与 `CreateCover` 调用，
   按"中心 ± 尺寸/2"算 AABB。本文第 2 节的缝宽/面积即由此得出。
2. **可涂面积与覆盖率上限**：Play Mode 下
   `script.eval` 读 `InkSurfaceController.Instance.Grid.PaintableCount` 与 `MapSize`，
   与 400×400 对比即可看出 blocked 扣了多少。
3. **越界**：Play Mode 下把本地玩家 `transform.position` 设到 `(0, 1.3, ±27.5)`（靠背顶），
   试跳上边界墙，再观察是否掉出场外且没有回收。
4. **Bot 是否进出生区**：`F12` 打开 DebugOverlay，或在 `BotController` 决策点临时 `Debug.Log`
   目标点，观察 2 分钟局里是否有 `|z| > 21.4` 的涂地目标。
5. **死缝可走性**：`ArenaNavigator.Instance.Grid.TryGetNearestWalkable(缝中心, out p)`，
   返回点与缝中心的距离 > 0.5m 即说明该缝在 Bot 眼里不可走。
6. **顶面计分一致性**：对集装箱顶与木箱顶各打一发，比较 `GetCoveragePercent` 的前后差值；
   集装箱顶差值应为 0，木箱顶应 > 0。
7. **相机**：`screenshot --view game` 只拍相机；带 uGUI 的界面用
   `script.eval --code 'UnityEngine.ScreenCapture.CaptureScreenshot("Logs/ui.png");'`。
